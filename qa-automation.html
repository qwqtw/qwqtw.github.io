01 · COVERAGE

Beyond checking a button click.

The framework tests a banking workflow at multiple layers, including successful and rejected transfers, backend state, and accessibility checks.

01 / UI

Browser workflow tests

Verify dashboard balances, transfer confirmations, transaction history, invalid amounts, and insufficient-funds behavior.

02 / API + E2E

State checked twice

Create accounts through test endpoints, execute transfers through the UI, and verify both frontend state and REST API transaction records.

03 / ACCESSIBILITY

Accessibility checks

Use axe-core with Playwright to flag serious and critical violations under WCAG 2.0 A / AA checks.

02 · IMPLEMENTATION

Repeatable tests, isolated state.

Stateful tests create dedicated accounts through a mock API, reducing shared-data collisions during parallel execution. Page Object Model classes keep browser interactions reusable.

STEP 01Provision account

Create a fresh account with a known balance through the mock API.

STEP 02Run browser flow

Open the matching account and perform a transfer through React UI.

STEP 03Verify API state

Assert updated balances and corresponding transaction records via REST endpoints.

STEP 04Collect diagnostics

Retain HTML reports and failure screenshots, traces, and videos for debugging.

03 · TOOLING & DELIVERY

Designed for engineering workflows.

Tests are organized into smoke, regression, API, and accessibility groups. The repository includes GitHub Actions automation, containerized test execution, and a Google Cloud Build configuration.

01Cross-browser coverage

Chromium, Firefox, and WebKit projects share reusable UI tests.

02CI and reporting

GitHub Actions is configured to run Playwright on pushes and pull requests, uploading HTML reports as artifacts.

03Portable test setup

Docker execution and a separate Cloud Build configuration describe repeatable local and cloud-based test runs.
